الخلاصة أولاً

العدّاد لم يعدّ خطأً، ولم يعدّ ضِعفاً. عدّ صحيحاً طوال الليل — لكنّ بوّابة الإرسال كانت مغلقة، والعدّ تراكم خلفها.

ولأن التراكم لم يكن يُلغى بل يُؤجَّل، فحين انفتحت البوّابة خرج كلّه دفعةً واحدة، ووصل النظام في اللحظة نفسها. فسجّله في الدقيقة التي وصل فيها — لا في الساعات التي حدث فيها.

القفزة ليست خطأ في العدّ. هي خطأ في التوقيت. الرقم صحيح؛ الدقيقة التي وُضع فيها خاطئة بستّ عشرة ساعة.

ما رأيته على الشاشة

ثلاث دقائق فقط، في ثلاث ماكينات، حملت كل الفائض. السقف الميكانيكي للخط ٤٥ قطعة في الدقيقة — وهو الرقم الذي يجعل هذه الدقائق مستحيلة لا مشبوهة فقط.

الآلية

في الايدج، كل عدّاد يحمل رقمين:

الرقمان اللذان يفسّران كل شيء

الرقممعناهمتى يتقدّم
accumulated كل نبضة رآها العدّاد منذ بداية الأمر دائماً — مع كل نبضة، بلا شرط
synced ما أُبلِغ به أمر التشغيل فعلاً فقط عند نجاح الإرسال

الفرق بينهما هو ما لم يُبلَّغ بعد. وفي الحالة الطبيعية يكون صفراً أو نبضات قليلة. المشكلة أن بوّابة الإرسال كانت مغلقة، بينما accumulated يواصل التقدّم.

السطر المسؤول

apps/edgegateway/src/acquisition/counter.service.ts · قبل الإصلاح

// observe() — يعمل مع كل نبضة، بلا أي شرط
mem.accumulated += inc;          // ← يتقدّم دائماً

// writeBatch() — يعمل عند كل إرسال
if (!c.joId || !c.running) continue;   // ← يتخطّى الإرسال…
//                                          …و synced يبقى مكانه

const delta = accumulated - mem.synced;   // الفجوة تتّسع بلا حدّ

continue يتخطّى الإرسال، لكنه لا يُلغي ما تراكم. فالفرق يظلّ محفوظاً، ينتظر أول لحظة يصبح فيها الشرط صحيحاً.

طوال الليل قرأت الماكينات IDLE وSTARVED (‏M1 كانت IDLE في 982 دقيقة من 983). فبقيت البوّابة مغلقة، والعدّ يتراكم خلفها. وفي 05:54 صارت الحالة RUNNING — وخرج كل شيء في إرسال واحد.

ولماذا انحشر كلّه في دقيقة واحدة

لأن كاتب الدقائق لا يسأل «كم أُنتج في هذه الدقيقة». يسأل سؤالاً آخر تماماً: 

// oee-standard.writer.ts
goodParts = MAX(0, toBase(jo.actualQtyGood) - SUM(الدقائق المحجوزة))
//          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//          «كم زاد الإجمالي منذ آخر مرة» — لا «كم أُنتج الآن»

هذا التصميم سليم ومقصود: يجعل مجموع الدقائق مطابقاً لإجمالي أمر التشغيل دائماً، مهما ضاعت رسالة أو تأخّرت. لكنه يعني أيضاً أن الكاتب يثق بالإجمالي ثقةً كاملة.

فحين قفز actualQtyGood بمقدار ١٢٦٠ في لحظة، حجز الكاتب ١٢٦٠ في تلك الدقيقة. لم يخطئ — نفّذ ما طُلب منه بالضبط. الخطأ حدث قبله بستّ عشرة ساعة.

الأثر الثاني — الذي لم تصطدم به بعد

حين صحّحت الأرقام يدوياً من الشوب فلور، صحّحت أمر التشغيل. لكن الدقائق المختومة لا تتغيّر. فصار عندك رقمان مختلفان لنفس الشيء — وهو ما رأيته في Output and time.

والأسوأ: انظر إلى MAX(0, …) في المعادلة أعلاه.

لماذا كان الإنتاج القادم سيختفي

الدقائق المحجوزة  = 1699    (الرقم المتضخّم)
أمر التشغيل بعد التصحيح = 1201

delta = MAX(0, 1201 - 1699) = MAX(0, -498) = 0

↳ وسيبقى صفراً حتى يتجاوز الإنتاج الحقيقي 1699 من جديد.
↳ أي أن 498 قطعة قادمة كانت ستُسجَّل كـ «لا شيء».

سكربت المطابقة يمسح هذا الدَّين أيضاً: بعد تشغيله يصبح مجموع الدقائق مساوياً لإجمالي أمر التشغيل تماماً، فيعود الفرق إلى الصفر — والإنتاج الجديد يُسجَّل طبيعياً من أول قطعة.

ما تغيّر

قاعدتان بدل شرط واحد

// كان: شرط واحد يحتجز الحالتين
if (!c.joId || !c.running) continue;

// صار: كل حالة تُعالَج بما تستحقّ
if (!c.joId) {              // لا أمر تشغيل أصلاً →
  mem.synced = accumulated;   // تُسقَط، لا تُدَّخر
  this.orphaned.set(…);       // وتُحصى، لتكون مرئية
  continue;
}
// أمر EXECUTING + نبضة = وحدة صُنعت → تُحجَز فوراً،
// مهما قال محرّك الحالة عن الماكينة.
  1. ١

    نبضة بلا أمر تشغيل تُسقَط وتُحصى

    نبضة تصل ولا أمر تشغيل خلفها لا تخصّ أيّ أمر — فلا يجوز أن تُنسَب إلى أوّل أمر يبدأ بعدها. تُسقَط، لكن تُسجَّل في عدّاد منفصل: عدّاد يدور بلا جدولة خبرٌ يستحقّ أن يُرى، سواء كان الخطّ يتحرّك خارج أمر أو المدخل يلتقط ضوضاء.

  2. ٢

    حالة الماكينة لم تعد تحجز العدّ

    أمر EXECUTING ونبضة على المدخل يعنيان أن وحدة صُنعت. رأي محرّك الحالة لا يُلغي وحدة مادية. وحجزُ العدّ لم يكن يُسقطه أصلاً — كان يدفعه لاحقاً في الدقيقة الخطأ، وهكذا حملت دقيقة STARVED ألفين ومئة قطعة.

اختبار في مجموعة الايدج يعيد إنتاج قفزة 25–26 أغسطس بالقاعدة القديمة ويثبت اختفاءها بالجديدة — فالخطأ صار مرئياً لا موصوفاً، ولا يمكن أن يعود دون أن يسقط الاختبار.

       count(*) FILTER (WHERE o."goodParts" > 0) AS of_which_counted

GROUP BY 1 ORDER BY 1;
