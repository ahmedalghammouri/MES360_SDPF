4 · How a signal is read

Every status point is a discrete input — a boolean contact, not a status word. That follows NCC's I/O specification: the remote I/O modules provide 8 digital inputs each, and the meaning of each input is declared per tag rather than compiled in:

Signal roleMeaning
RUN_MODEON = running or ready with nothing to process. It does not by itself distinguish working from waiting.
RUN_MODE_PULSEDSteady ON = running, pulsing = stopped, OFF = alarm. Judged by how often the bit changes, not by its level.
PROCESSINGProduct is actually being worked. This is what separates a machine that is producing from one that is merely ready — see document 26.
INFEED_AVAILABLE / OUTFEED_BLOCKEDMaterial-flow signals. A measurement here always outranks inference from neighbouring machines.
All of the above — the role, the pulse window, the idle threshold, and what each resulting state costs in downtime and OEE — is edited in the application (IoT → Signal Rules) or on the edge gateway's own dashboard. None of it requires a new build.
