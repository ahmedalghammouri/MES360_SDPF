3 · Why counting happens at the edge

The gateway polls at 100 ms and counts edges locally. A pulse that exists only between two server polls is a pulse that would otherwise never be counted, and production figures that drop units during a network blip are not figures anybody can act on. The gateway also buffers to disk, so a break in the link to the platform delays the data without losing it.

4 · How a state becomes a number

StepWhereWhat happens
1L1 → L2A discrete input is read and interpreted through its signal role — level, or rhythm for a pulsing signal.
2L2Run Mode says the machine is able to work. A Processing signal says whether it is. Ready-but-idle is classified against the line as STARVED or BLOCKED, never guessed when there is no signal to support it.
3L2A state rule decides what that state costs: whether it opens a downtime event, whether it is planned, which reason code it carries, and whether it is charged against OEE. Editable per factory and per machine.
4L2 → L3The event and the counts are written to the platform; per-minute snapshots become the fact store the KPIs read.
5L3External losses (STARVED / BLOCKED) are removed from planned production time before Availability and Performance are derived, so a machine is not punished for waiting on the line.
Nothing in steps 1–3 is compiled in. Signal roles, pulse and idle thresholds, state rules and alarm limits are all rows in the database, edited from the application or from the edge gateway's own dashboard. That is deliberate: which contact means what, and what a stop costs, are plant decisions — a customer should not need a redeploy to change one.

5 · Resilience

FailureBehaviour
Platform unreachableThe gateway keeps polling, counting and evaluating alarms; readings buffer to disk and flush when the link returns.
Gateway restarted mid-stopCounter state is restored from disk; an open downtime or alarm event is adopted rather than duplicated.
A sensor reads BAD qualityIt is ignored for classification. Acting on a reading the gateway itself distrusts would put a wrong reason into the downtime log.
A contact chattersA configurable settling time per state prevents an event per poll.
